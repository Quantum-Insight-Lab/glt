# Инварианты сборки (S-1…S-10)

Инвариант домена защищает корректность фактов. **Инвариант сборки** защищает единственность и направление механизмов в кодовой базе. Это разные классы: PROTO-xx и INV-xx можно соблюсти полностью и при этом получить две реализации обработки ошибок и доменное правило в контроллере.

Правило внесения: запись появляется здесь **только вместе с работающей проверкой**. «Договорились так делать» живёт в [`AGENTS.md`](../../../AGENTS.md), и это другой уровень надёжности.

Проверка формата и стиля к этому классу не относится. Относится только то, нарушение чего приводит к расхождению реализаций или к обходу домена.

## Каталог

| ID | Инвариант | Механизм | Режим |
|---|---|---|---|
| S-1 | `domain` не импортирует I/O, API, UI, инфраструктуру | dependency-cruiser | блокирующе |
| S-2 | Импорты между пакетами идут только по объявленному направлению | dependency-cruiser allowlist | блокирующе |
| S-3 | Каждый `event_type` существует в Event Registry; типы генерируются | реестр + кодогенерация + скан источников | блокирующе |
| S-4 | Один механизм на одну задачу | реестр механизмов + тест-перепись | блокирующе |
| S-5 | Производный артефакт не пишет в авторитетный источник | dependency-cruiser + тест | блокирующе |
| S-6 | Нет циклических зависимостей между модулями | `dependency-cruiser` правило `s6-no-circular` | блокирующе |
| S-7 | Каждый инвариант имеет тест, ссылающийся на его ID | сверка имён тестов с реестрами | блокирующе |
| S-8 | Константы читаются только из `parameters/` | скан числовых литералов в domain | предупреждение → блок |
| S-9 | Мёртвый код и неиспользуемые экспорты не накапливаются | `knip` | предупреждение |
| S-10 | Поверхность CLI равна списку разрешённых capabilities | тест равенства множеств | блокирующе |

Порядок внедрения — раздел [Внедрение](#внедрение).

## S-1 — domain без I/O

| Поле | Значение |
|---|---|
| **Формулировка** | `packages/domain` не импортирует ничего, что выполняет I/O: файловую систему, сеть, процессы, БД, а также `api`, `dashboard`, `cli`, `collectors`, `runner`, `audit`. |
| **Что ломается без него** | Доменные правила уезжают в адаптеры, ядро нельзя переиспользовать и нельзя тестировать без окружения. Канонизатор и обход графа перестают быть детерминированно проверяемыми. |
| **Механизм** | `dependency-cruiser`, правила `s1-domain-no-io-core`, `s1-domain-no-third-party`, `s1-domain-no-siblings`: запрет на I/O-модули ядра, на любые сторонние пакеты и на все sibling-пакеты кроме `contracts`. |
| **Где проверяется** | CI на каждом PR |
| **Режим** | блокирующе с DEV-01 |
| **Нарушение** | `import { readFileSync } from "node:fs"` в `packages/domain/src/canonical.ts` |
| **Легальные исключения** | `node:crypto` для sha256 и Ed25519 — единственное разрешённое ядровое исключение, потому что альтернатива это сторонняя зависимость в базе доверия bootstrap verifier. Вносится в конфиг как именованное исключение, не как отключение правила. |
| **Владелец** | engineering |

## S-2 — направление импортов

| Поле | Значение |
|---|---|
| **Формулировка** | Импорт между пакетами разрешён только по объявленному в конфиге направлению: пакет достаёт лишь до слоёв, объявленных ниже него. `cli` и `api` — **композиционные корни**: они связывают пакеты и не реализуют доменной логики, поэтому им разрешён любой слой. |
| **Что ломается без него** | Контексты срастаются, и деление работы по границам ([`../00-governance/parallel-work.md`](../00-governance/parallel-work.md)) перестаёт работать: конфликт переносится в код и обнаруживается на merge. |
| **Механизм** | `dependency-cruiser` с явным allowlist рёбер, а не списком запретов. Новое ребро — правка конфига в отдельном PR. |
| **Где проверяется** | CI на каждом PR |
| **Режим** | блокирующе с DEV-01 |
| **Нарушение** | `packages/collectors` импортирует `packages/runner` |
| **Легальные исключения** | `packages/contracts` (генерируемые типы) импортируется всеми. Тестовые файлы могут импортировать любой пакет; правило применяется к `src/`, не к `test/`. |
| **Владелец** | engineering |

До 0.7.0 формулировка требовала, чтобы `cli` не импортировал `registry` напрямую. Это оказалось несовместимо с поверхностью CLI: команда `glt compile registry` обязана вызвать компилятор реестра, а фасадного пакета между ними нет и заводить его не за чем. Исключение для композиционных корней — узкое и названное: правило «только ниже по списку» продолжает действовать для всех остальных пакетов, где оно и защищает границы контекстов.

С волны 3, когда появляется Event Core, межконтекстная связь во время исполнения идёт через зарегистрированные события, а не через прямой вызов. До этого граница держится только на импортах.

## S-3 — Event Registry как единственный источник имён

| Поле | Значение |
|---|---|
| **Формулировка** | Каждый `event_type` существует в [`../../contracts/events/event-registry.yaml`](../../contracts/events/event-registry.yaml). Типы и валидаторы генерируются из реестра. Строковый литерал имени события в коде — ошибка сборки. |
| **Что ломается без него** | Два имени одного факта, расхождение схем, дубли в проекциях. Реестр перестаёт быть источником правды в тот момент, когда в коде появился первый литерал мимо него. |
| **Механизм** | Кодогенерация в `packages/contracts` + тест, сканирующий все источники на имена из реестра + счётчик `registry_drift`. Скан, а не eslint: правило линтера не знает множество допустимых имён, а тест читает реестр и знает его точно. |
| **Где проверяется** | CI на каждом PR |
| **Режим** | блокирующе с DEV-01; пока событий не эмитится, проверка проходит тривиально |
| **Нарушение** | `emit("glt.snapshot.compiled", …)` вместо `emit(EventType.SnapshotCompiled, …)` |
| **Легальные исключения** | Нет. Чтение имени из фикстуры в тесте не является `emit`. |
| **Владелец** | engineering |

## S-4 — один механизм на одну задачу

| Поле | Значение |
|---|---|
| **Формулировка** | Ровно одна реализация на каждую задачу из реестра механизмов: валидатор JSON Schema, канонизатор, функция digest, парсер YAML, тип ошибки, писатель вывода CLI, загрузчик параметров, подпись Ed25519. |
| **Что ломается без него** | Дрейф реализаций. Каждый следующий исполнитель копирует ближайший образец, и через месяц в репозитории два способа считать digest — то есть два ответа на PROTO-03. |
| **Механизм** | Реестр механизмов в [`AGENTS.md`](../../../AGENTS.md) закрывает вопрос на входе; тест-перепись считает реализации и падает при значении больше одного. |
| **Где проверяется** | CI на каждом PR |
| **Режим** | блокирующе с DEV-04 |
| **Нарушение** | Второй вызов `crypto.createHash("sha256")` вне `packages/domain/src/digest.ts` |
| **Легальные исключения** | Сторонняя библиотека может использовать свой механизм внутри себя. Правило применяется к нашему коду. Замена механизма — PR, который удаляет старый, а не добавляет второй. |
| **Владелец** | engineering |

## S-5 — производное не пишет в авторитетное

| Поле | Значение |
|---|---|
| **Формулировка** | Производный артефакт не пишет в источник, из которого выведен: `dashboard` не пишет ничего кроме запросов действий через API, `runner` не пишет в registry, компилятор не принимает сгенерированный снимок как вход для той же revision. |
| **Что ломается без него** | Тихая порча инвариантов домена и круговая проверка: снимок начинает подтверждать сам себя. Это антипаттерн раздела 8 и правило 5 из [`../00-governance/normativity-rules.md`](../00-governance/normativity-rules.md). |
| **Механизм** | `dependency-cruiser` на направление записи + тест: подать снимок на вход компилятора той же revision → отказ. |
| **Где проверяется** | CI на каждом PR |
| **Режим** | блокирующе с DEV-06 |
| **Нарушение** | `packages/runner` импортирует writer из `packages/registry` |
| **Легальные исключения** | `snapshots/` — каталог вывода, в него пишет только компилятор снимков. |
| **Владелец** | engineering |

## S-6 — нет циклов между модулями

| Поле | Значение |
|---|---|
| **Формулировка** | Граф импортов между модулями и пакетами ацикличен. |
| **Что ломается без него** | Порядок сборки становится неопределённым, рефакторинг блокируется, генерация типов получает неустойчивый порядок и ломает байтовую стабильность вывода. |
| **Механизм** | `dependency-cruiser`, правило `s6-no-circular`. Отдельный детектор циклов не заводится: dependency-cruiser уже разрешает TS-алиасы и видит полный граф, а второй инструмент на ту же задачу — нарушение S-4. |
| **Где проверяется** | CI на каждом PR |
| **Режим** | блокирующе с DEV-01 |
| **Нарушение** | `impact` → `snapshot` → `impact` |
| **Легальные исключения** | Циклы в **данных** допустимы и ожидаемы: топология может содержать цикл, execution DAG — нет (PROTO-07). Правило касается только графа импортов. |
| **Владелец** | engineering |

## S-7 — каждый инвариант имеет тест со своим ID

| Поле | Значение |
|---|---|
| **Формулировка** | Для каждого ID из трёх реестров существует хотя бы один тест, чьё имя содержит этот ID: `PROTO-xx` ([`invariants.md`](invariants.md)), `INV-xx` ([`../PDA/04-invariants.md`](../PDA/04-invariants.md)), `S-x` (этот документ). |
| **Что ломается без него** | Инвариант остаётся текстом в спеке, а целостность держится на памяти архитектора. Работает при одном исполнителе, отказывает при двух. |
| **Механизм** | Скрипт сверки: парсит ID из трёх реестров, парсит имена тестов, выдаёт разрыв и метрику `structural_coverage`. |
| **Где проверяется** | CI на каждом PR |
| **Режим** | сначала аудит с отчётом, затем блокирующе с DEV-04 |
| **Нарушение** | PROTO-08 присутствует в реестре, ни один тест не содержит `PROTO-08` |
| **Легальные исключения** | Инвариант, относящийся к волне, которая ещё не реализована, помечается в реестре как отложенный с указанием шага DEV. Отложенный не считается покрытым и виден в метрике; молча пропустить его нельзя. |
| **Владелец** | engineering |

## S-8 — константы только из parameters/

| Поле | Значение |
|---|---|
| **Формулировка** | Числовые константы поведения читаются через загрузчик параметров из [`../../parameters/`](../../parameters/). Литерал в `packages/domain` запрещён. |
| **Что ломается без него** | Числа расползаются по коду, и калибровка parameter cards становится невозможной: значение в карточке перестаёт совпадать с поведением. |
| **Механизм** | Тест, сканирующий `domain` на числовые литералы вне allowlist `[-1, 0, 1, 2]`, с именованным исключением по файлам + тест, что каждая карточка из `parameters/` читается хотя бы одним модулем. |
| **Где проверяется** | CI |
| **Режим** | предупреждение с DEV-01, блокирующе с DEV-10 |
| **Нарушение** | `if (depth > 8)` вместо `if (depth > params.impact.max_traversal_depth)` |
| **Легальные исключения** | Константы формата, а не поведения: длина hex-строки sha256, размер блока, номер версии схемы. Вносятся именованными константами рядом с определением формата. |
| **Владелец** | parameters |

## S-9 — нет мёртвого кода

| Поле | Значение |
|---|---|
| **Формулировка** | Неиспользуемые экспорты, файлы и зависимости не накапливаются. |
| **Что ломается без него** | Исполнители дублируют то, что уже есть, но не видят. Прямо усиливает S-4. |
| **Механизм** | `knip` с отчётом в CI. |
| **Где проверяется** | CI |
| **Режим** | предупреждение |
| **Нарушение** | Экспортированная `resolveAliasLegacy`, не используемая ни одним пакетом |
| **Легальные исключения** | Публичный API пакета, предназначенный для внешнего потребителя, помечается в конфиге `knip` как entry point. Генерируемые типы исключаются целиком. |
| **Владелец** | engineering |

## S-10 — поверхность CLI равна allowlist

| Поле | Значение |
|---|---|
| **Формулировка** | Множество команд, зарегистрированных в `packages/cli`, в точности равно множеству из [`cli.md`](cli.md). Ни одна команда не отображается на capability вне списка `inventory`, `validate`, `compile`, `typecheck`, `test`, `health`. |
| **Что ломается без него** | v1 обещает отсутствие `commit`, `push`, `deploy`, `self_upgrade` и `self_write`. Без механизма это обещание держится на внимательности ревьюера, а добавить скрытую подкоманду — три строки. |
| **Механизм** | Тест равенства множеств: список команд из парсера против списка из `cli.md`, плюс запрет любой команды, чей executor не имеет ActionSpec с `declared_risk: read`. |
| **Где проверяется** | CI на каждом PR |
| **Режим** | блокирующе с DEV-01 |
| **Нарушение** | Скрытая `glt push --force` или флаг `--write`, меняющий рабочую копию |
| **Легальные исключения** | Нет. Расширение поверхности — правка `cli.md` и отдельный PR с обоснованием, ревью архитектора. |
| **Владелец** | engineering |

## Внедрение

Порядок из раздела 9.11 патча, от того, что ломается первым.

**DEV-01 — сделано.** S-1, S-2, S-5, S-6 в [`.dependency-cruiser.cjs`](../../../.dependency-cruiser.cjs), S-3 и S-8 тестами-сканами, S-10 сверкой множества команд с `cli.md`. Все в блокирующем режиме, каждый механизм проверен негативно: нарушение вносится намеренно, прогон обязан упасть. Шесть таких прогонов, шесть падений.

**DEV-04 — сделано.** S-7 блокирует сверкой имён тестов с тремя реестрами; отложенные ID видны и непокрыты. S-4 — тест-перепись реестра механизмов; второй `createHash("sha256")` вне `digest.ts` роняет прогон. S-9 остаётся предупреждением.

**DEV-05 — сделано.** INV-01 снят с отложения: `glt lint authority` блокирует двух владельцев одного класса и один путь у двух владельцев. Конфликт — `source_conflict`, код 6; правило `registry_vs_engineering` победителя не выбирает.

**DEV-06 — сделано.** PROTO-01, PROTO-02, PROTO-08, PROTO-09 и INV-02 сняты с отложения: `glt compile registry` строит уникальный индекс alias и падает на неизвестном/неоднозначном имени, переназначении внутри той же версии и смене смысла без revision.

**DEV-07 — сделано.** `glt resolve`: `path` от корня репозитория, не от корня пакета; нет файла — код 5; неоднозначный locator — PROTO-02, не первый хит.

**DEV-08 — сделано.** PROTO-03, PROTO-05, PROTO-10 и INV-03 сняты с отложения: `glt compile snapshot` канонизирует JCS, материализует defaults, требует pin.

**DEV-09 — сделано.** Golden digest заморожен компилятором; freeze-check отвергает placeholder. Второй boundary `glt.controlplane-intended@1` собирается из DEV frontmatter.

**DEV-10 — сделано.** `glt impact`: обход по матрице, `known_unknowns` на uncovered relation и за boundary, check не в `affected_nodes`. PROTO-07, INV-05 и INV-12 сняты с отложения. S-8 блокирующе: глубина обхода только из `parameters/`.

**DEV-11 — сделано.** Инъекции S1–S3 в CI; открытый набор seeded changes с ручной ground truth на `glt.seeded-slice@1`. Независимое ревью записано как limitation. Holdout не открывался.

**Дальше, по мере появления боли:** S-5 с DEV-06, S-9, метрики слоя «Сборка» на дашборд устойчивости.

**Правило остановки:** расширение этого реестра не начинается, пока S-1, S-2, S-3, S-7 и S-10 не работают в блокирующем режиме. Инвариант сборки без механизма возвращает методологию к состоянию пожеланий и обесценивает патч.
